TITLE: Anthropic Rebuilt the API Behind Claude. The Old One Had the Final Word.
OUTLET: The 420.in

Anthropic says it moved the main interface through which customers and its own applications access Claude from Python to Rust, reducing the server processor work needed for each request. The company published an account of the migration on November 25. It reports using about 70 per cent less CPU per request and cutting the median time before a response begins by about 20 per cent.
The rewrite concerned the Messages API, the software that receives requests, prepares them for the model and sends results back. Anthropic says it made the transition without taking the service offline or suspending feature development. The engineering question was how to establish that both versions behaved alike once real customers were using them.
What Was Making the Old Service Expensive to Run?
Anthropic says average daily request volume on its own platform increased roughly 1,800-fold between early 2024 and autumn 2026. Over that period the interface did more than pass along a message. It took on work including checking incoming requests and managing the tokens flowing from the model. Each operation contributed to the processor load of running the service.
The company initially rewrote part of the system in Rust and called it from Python. Anthropic says that change lowered CPU use but introduced overhead as information moved between two languages. A fuller rewrite offered a chance to remove that boundary. It also exposed the organisation to the risk of disrupting behaviour that customers had come to rely on.
One user might send an unusual combination of options that works in the existing service. A customer may have developed software that expects an error in a particular form. A conventional test suite can cover known cases, but a production service accumulates many behaviours that may only become visible when somebody depends on them.
How Did Engineers Check the Rewrite?
Anthropic says it used the existing Python service as a point of comparison while testing the Rust system on production traffic. Giving the newer system a chance to handle the same workload made it possible to identify where the versions diverged before trusting the new one more broadly. The comparison gave teams a way to direct their attention to differences that mattered.
AI was part of the project. Anthropic says Claude produced a first version of the core request path in about a week and that agents were used to help address differences. Finding an answer quickly was easier once the engineers had something against which to judge it. Where the model could respond differently to the same input, a difference did not automatically mean the API itself had made an error.
The difficulty of making that distinction is easy to overlook in an AI software project. There is no single expected text response to every open-ended chat request. The system surrounding the model still has observable duties, such as handling a request correctly and returning the information software clients expect. The migration depended on deciding which differences represented a change in that surrounding behaviour.
What Do the Performance Numbers Mean?
Reduced CPU work at the interface can make it cheaper to serve the same traffic and can free engineering capacity when usage rises. Faster time to the first token measures how quickly the start of a response reaches the customer. It does not describe how long every full response takes. Both figures are from Anthropic’s own service and describe this migration.
For other engineering teams, the more transferable idea is to use a running service to test how a replacement behaves, especially when existing tests miss some of the ways customers use it. That approach still requires attention to information handling, operational limits and the ability to recover if something changes unexpectedly.
The project offers a concrete case for AI in technology operations. Anthropic used a model to help produce code and a production system to check what the code did. The practical result depended on having a way to tell when the old and new services differed.
