TITLE: Plumbing, not intelligence: Index Exchange on what MCP means for buyers
OUTLET: PPC Land

Index Exchange has published a guide for media buyers that describes Model Context Protocol as the plumbing of agentic advertising rather than its intelligence, and argues that having an MCP server "has quickly become table stakes." The page, titled "What Model Context Protocol (MCP) Means for Media Buyers," sits in the company's Index Explains video series under the topic "AI and agentic" and carries the byline of Mike Mullin, senior product manager. It has no publication date. Its text links to an Index Exchange post dated November 13, 2026, which places it after that day.
What the page offers is a vocabulary, not a product. It defines the protocol, separates it from the servers built on it, splits the agentic stack into three parts and walks through a single workflow: an AI agent diagnosing a programmatic deal that has stopped delivering. It does not say whether Index Exchange operates an MCP server of its own.
In Short
Index Exchange has published a plain-language guide to Model Context Protocol, the open standard that lets AI assistants such as ChatGPT and Claude pull data from other software and act inside it. It matters to media buyers because ad platforms on both sides of programmatic trading are adding MCP connections, and the guide uses a stalled deal to show what an AI agent could check and propose. The page explains how the pieces fit together, but it does not say whether Index Exchange runs an MCP server itself or when buyers could use one.
What the page says MCP is
According to Index Exchange, MCP "is a standard that Anthropic developed and open-sourced in late 2024." Anthropic introduced it on November 25, 2024. In December 2025 the protocol moved to the Agentic AI Foundation, a project of the Linux Foundation, according to the MCP project's blog - a change the Index Exchange page does not mention.
The page's core definition is short. "At its core, MCP is a standard way for AI systems to connect to external tools and data sources and interact with them in real time," it states. Before the protocol, according to the page, every AI system needed a custom integration for every tool or data source it wanted to reach. "Now, with MCP, developers can build to one shared protocol instead."
Two comparisons follow. The first frames MCP as the next step after an application programming interface, a standard way for different applications to understand each other when they reach for tools and data. The second is a hardware analogy that other trade press explainers have also reached for: "MCP is like a USB-C for AI." Neither comparison is new, but both are aimed at buyers who have heard the acronym in meetings without seeing a definition.
The page also makes a claim about cost and disruption. "MCP doesn't replace or rebuild the systems you already use," it says. Existing platforms, according to Index Exchange, "become more usable without needing to be rebuilt from scratch."
Protocol versus server
One distinction on the page is easy to miss in trade coverage, where the two terms are used loosely. Index Exchange acknowledges this directly: "you'll often hear MCP and MCP server used interchangeably." The protocol, it says, is "the shared language that defines how an AI system and a tool or data source should talk to each other." A server is something a company builds on top of it. "An MCP server is what a company or platform builds using that protocol to allow access to its own tools and data."
So when a platform says it has an MCP server, the page explains, it has built an interface using the MCP standard. "Every MCP server speaks the same underlying protocol, which is what makes this scalable."
Server, agent and skill
The most structured part of the page breaks the agentic ecosystem into three components. Each comes with a one-line role and a qualifier.
The framing is notable for what it withholds from the server. Many of the MCP announcements PPC Land has covered since 2025 presented the server itself as the news. Index Exchange, which operates a supply-side platform, places the judgment in the agent and the reusable know-how in skills, and treats the server as necessary but inert.
Five workflows named for programmatic
MCP is not specific to advertising, the page notes, but programmatic trading has always depended on APIs to connect demand-side platforms, SSPs and measurement platforms. According to Index Exchange, MCP "builds on that same foundation." Instead of moving between dashboards, buyers and sellers can query in natural language. The page lists five workflows:
- Creating audiences
- Identifying and packaging inventory
- Managing and troubleshooting deals
- Setting up campaigns
- Managing campaign pacing and delivery
Only one of the five receives a worked example.
How the deal troubleshooting example works
The page uses a deal that stops delivering - the kind of private arrangement a buyer targets through a deal ID - to illustrate the sequence. According to Index Exchange, the example runs in five stages:
- The question. A user asks an AI tool, with ChatGPT and Claude named as examples, "Why isn't my deal delivering?"
- Data retrieval. "Behind the scenes, the MCP server connects to the platform, retrieves the necessary data, and returns it to the assistant for diagnosis."
- The bid funnel walk. An agent checks four points to find where things break down: deal status, DSP bidding activity, bid blocks and creative audits. It then surfaces the likely root cause.
- Recommendations. The agent proposes next steps. The page names three: requesting a fix from the DSP seat, temporarily reinstating a previous creative "to keep the deal delivering," or notifying the team that owns the asset.
- Human approval. "The agent surfaces the options and does the legwork, then you decide what actions to approve."
The sequence is close to an integration PPC Land has already reported on. In April 2026, AdRoll and PubMatic connected AdRoll's buy-side agents to PubMatic's diagnostics over MCP, pulling root-cause analysis for underdelivering deals - pacing limits, creative blocks, publisher-side factors - and leaving decisions to people. PPC Land described that work at the time as one of the first cross-platform agent diagnostics demonstrated in programmatic, with a narrow scope and no disclosed scale. Index Exchange's page presents its version as an illustration. It does not name a DSP, a deal, a time saving or a client.
"This is just one example, but it shows why MCP matters," the page states. "An MCP server has quickly become table stakes."
What the page leaves out
The page does not state whether Index Exchange operates an MCP server, which tools or data such a server would expose, whether the troubleshooting example runs on Index Exchange's platform today, which AI clients are supported beyond the two named, how access is authenticated or permissioned, or what it costs. There is no date for the page or its video. The intro calls Mullin a "product manager" while the byline reads "Senior Product Manager."
Where Index Exchange already stands on agents
The guide arrives from a company that has spent 2026 building infrastructure for a different layer of agentic trading. On February 12, 2026, chief executive Andrew Casale told IAB's Annual Leadership Meeting that decisioning should move to the exchange, arguing that external compute imposes a "cloud tax" and citing a February 2026 case with a 75% cut in cost per site visit. The talk, as reported, did not touch on MCP.
The practical expression of that argument is Index Cloud, which runs partner code inside Index Exchange's own data centers. In April 2026, Bedrock became the first DSP to run its bidder inside the exchange, with Index Exchange stating a container execution window of under five milliseconds; Index Cloud was then in closed beta with Chalice AI, inPowered AI and Nano Interactive among the named partners. On September 10, 2026, PMG began a pilot running its streaming TV buying inside Index Cloud through Bedrock's containerized DSP, with access to more than 3,000 media owners and no performance figures disclosed.
Those containers follow IAB Tech Lab's Agentic RTB Framework, which Index Exchange's own series calls the Agentic Real-Time Framework. When the framework's version 1.0 opened for public comment on November 13, 2025, it required OCI-compliant containers communicating over gRPC or MCP, and Index Exchange was part of the working group alongside OpenX, The Trade Desk and Chalice. The MCP page lists the ARTF explainer as further reading and closes on the same theme: "Standardization makes the agentic future possible, and getting the plumbing right is how we get there."
There is a distinction between the two layers. Container work under ARTF concerns decisions made inside the auction within milliseconds. The MCP page concerns the slower, human-facing work around deals and campaigns - questions typed into a chat window. Index Exchange is making the case that both need standard plumbing, but only the first has a product with named partners behind it.

Why this matters for the marketing community
An SSP telling buyers that an MCP server is "table stakes" is a statement about where platform competition is moving. If AI assistants become the place where buyers ask why a deal is stuck or how a campaign is pacing, platforms without a server risk falling out of the conversation - literally. That is the commercial logic behind the list above, and it may explain why an exchange would publish a primer on the subject.
The page's own framing also cuts against some of the louder claims in the market. Calling the server "not intelligence" concedes that connecting an assistant to a platform does not, by itself, diagnose anything. The quality of the agent and its skills does that work, and those are precisely the parts the page describes only in outline.
Practical limits have surfaced in PPC Land's coverage throughout 2026. Draft Digital replaced 12 separate MCP calls with a single buyer agent to control token costs when many platforms were connected at once. Security researchers have described tool poisoning attacks against MCP implementations, in which a malicious server feeds hidden instructions to the AI client. And Marketecture Media's Ari Paparo questioned whether data sellers' MCP servers can be trusted when those vendors have incentives to overstate what their segments contain.
Expectations for scale remain measured. In a July 2026 interview, Magnite chief executive Michael Barrett put his most optimistic forecast for agentic ad spend in 2027 at $600 million to $700 million.
Which leaves a question the page raises but does not answer: if an MCP server is table stakes, has Index Exchange put its own on the table?
