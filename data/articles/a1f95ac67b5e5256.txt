TITLE: AI agents linked to Amazon Ads get an optional upgrade on December 8
OUTLET: PPC Land

Amazon Ads will accept a newer version of the Model Context Protocol on its MCP Server from December 8, 2026, according to a release note that carries that date and was already listed in the Amazon Ads advanced tools release notes feed by November 23, 2026. The update covers MCP protocol version 2026-07-28. It is optional. Developers who have wired AI assistants into Amazon's advertising systems can leave their setups alone, and Amazon has set no date for switching off the older versions.
In Short
Amazon's server that lets AI assistants run ad campaigns will start accepting a newer version of the protocol those assistants speak on December 8, 2026. It affects agencies, sellers and software firms that connect tools such as Claude, ChatGPT or Kiro to Amazon Ads accounts. Nothing breaks that day: current connections keep working, the addresses, tools and logins stay the same, and the older versions have no end date.
What Amazon published
The entry sits at the top of the Amazon Ads advanced tools release notes under the heading "Amazon Ads MCP Server support for MCP protocol version 2026-07-28". It is dated December 8, 2026, the day support begins, rather than the day it was posted. The release notes feed that contains it was last built on November 23, 2026, at 19:32 GMT, which puts the notice at least 15 days ahead of the change. The entry below it, on a demand side fees API for agency fee management, is dated November 19, 2026.
The opening is two sentences long. "Starting December 8, 2026, the Amazon Ads MCP Server will support MCP protocol version 2026-07-28. Adoption is optional, and existing clients will not be automatically upgraded."
What follows is written as three questions and answers. On what the change is, Amazon wrote: "MCP 2026-07-28 introduces a stateless protocol model in which each request contains the information needed to process it. Clients using the new version send independent requests without establishing an MCP session, include client and protocol information with each request, use the Mcp-Method and (where applicable) Mcp-Name HTTP headers, can call server/discover for supported versions and capabilities, and receive additional result and caching metadata. Endpoints, tools, authentication options, and access controls are not changing."
On retirement of the older versions, the answer is short. "No decommission date is being announced. Earlier protocol versions remain supported. Any future deprecation will be communicated separately with advance notice and migration guidance."
On the migration path, the first sentence is "Existing clients need no action." The rest addresses developers who choose to move. The note closes by pointing to three connection guides, a protocol changelog and a support page: "Authentication is unchanged; see the Regular, Lite, and OAuth 2.1 connection guides. For protocol details, see the MCP 2026-07-28 changelog. For support or compatibility questions, visit the Support page."
What the server does, in plain terms
The Model Context Protocol, usually shortened to MCP, is an open standard that lets an AI assistant use outside software. The assistant sees a list of named functions, called tools, and decides which one to run and with what inputs, a pattern known as tool calling. The Amazon Ads MCP Server is Amazon's own implementation. It turns those tool calls into Amazon Ads API operations, so an assistant can create a Sponsored Products campaign, pull a report or list the accounts a user can reach, without the developer writing a custom integration for each operation.
The connection guide gives an example of a tool name: "campaign_management-delete_campaign". Tools follow a group-then-action pattern. When Amazon says "tools" are not changing, it means this catalogue of operations stays as it is.
What "stateless" means
Earlier versions of MCP worked a little like a phone call. Before doing any work, the assistant and the server exchanged a greeting - an "initialize" request followed by a "notifications/initialized" message - and the server could hand back a session number in a header called Mcp-Session-Id. The assistant then repeated that number on every later request, and the server had to remember who was on the line.
Version 2026-07-28 works more like a series of letters. Each one carries everything the server needs to answer it. According to the MCP changelog, the new version will "Make MCP stateless: remove the initialize / notifications/initialized handshake. Every request now carries its protocol version and client capabilities in _meta". The same document says the release will "Remove protocol-level sessions and the Mcp-Session-Id header from the Streamable HTTP transport."
What replaces the session for servers that still need to remember something between calls? The changelog's answer is that such "Servers that need cross-call state use explicit, server-minted handles passed as ordinary tool arguments". In practice, any reference the server needs comes back to it inside the request itself.
The Amazon Ads MCP Server already works close to this pattern for account selection, according to its connection guide. In its default mode, "The MCP server requires the account identifiers to be passed as a parameter in the request body." In the alternative fixed mode, the account identifiers travel as headers on each request. Neither mode depends on the server remembering an earlier exchange to know which advertiser account a call is for.
Four things clients gain
Amazon's note lists four additions for clients that move to the new version. The MCP changelog describes each in more detail.
The changelog ties the caching fields to cost as well as speed. It says servers "SHOULD return tools from tools/list in a deterministic order to enable client-side caching and improve LLM prompt cache hit rates." An assistant that receives the same tool list in the same order can reuse part of its earlier processing, which is what prompt caching refers to.

The migration path, as Amazon describes it
According to Amazon, a client that chooses version 2026-07-28 goes through five steps.
- Move to an MCP SDK or client that supports the new version. Amazon names the official TypeScript, Python, Go and C# SDKs, which it says "do, and handle client metadata and headers automatically".
- Configure that SDK or client "to request that version".
- Remove dependencies on "the legacy initialize and notifications/initialized handshake and on Mcp-Session-Id or transport-level session state".
- "Accept additive result and caching metadata", meaning the client should not fail when results carry new fields.
- "Test server/discover, tools/list, and representative tools/call requests before using the new version in production."
For everyone else, the instruction is a single line: "Existing clients need no action."
Three ways in: Regular, Lite and OAuth 2.1
The release note points to three connection guides. Amazon says none of them changes, and as they stood on November 25, 2026, none of the three guides mentioned protocol version 2026-07-28 or the word "stateless".
Server addresses
The guides list six addresses, two per region. According to the regular guide, "These URLs are not region agnostic."
Regular and Lite
The regular server registers every Amazon Ads operation as its own tool. The Lite server, which Amazon added on September 29, 2026, exposes three: search_tools, describe_tools and invoke_tool. The assistant searches the catalogue in plain language, reads the input schema of the tool it picked, then runs it. According to the Lite guide, this "keeps the model's context small and predictable regardless of how many operations Amazon Ads exposes". The guide describes the Lite version as "functionally equivalent to the Regular version".
The difference is about the model's context window, the amount of text an AI model can hold in view at once. A full tool catalogue can fill much of it before any work starts. The Lite guide adds one more detail: a single search returns every tool in the matched group, so later requests in the same area "can go straight to describe_tools and invoke_tool without issuing a new search_tools call". The guide calls this "a cache warmed by spatial locality". That memory lives inside the assistant's own conversation, not in a protocol session, which is why the Lite pattern does not rely on the feature that version 2026-07-28 removes.
Account modes and headers
Both versions support two ways of choosing which advertiser account a request acts on. In the default Dynamic Account Context mode, the assistant asks the user for account identifiers and passes them as parameters; a tool called query_advertiser_accounts lists the accounts a user can reach. In Fixed Account Context mode, the identifiers are set once as headers. The guide says that "for this mode, all headers should correspond with a single account."
None of these Amazon headers is affected by the update. The two new protocol headers, Mcp-Method and Mcp-Name, sit alongside them, and Amazon says the official SDKs add them automatically.
OAuth 2.1
The third guide covers OAuth 2.1, a sign-in method Amazon added to the server on July 6, 2026. Instead of pasting an access token into a configuration file, the user signs in through a browser window and the assistant software collects the token. The guide covers Kiro CLI, Claude Code, Claude Desktop and ChatGPT, and its callback table also lists Amazon Quick.
The guide lists the Login with Amazon values that some clients need entered by hand.
Each assistant has its own callback address, which must be added to the "Allowed Return URLs" of the developer's Login with Amazon security profile. Without it, according to the guide, the sign-in "will fail with a redirect URI mismatch error".
Amazon's statement that "Authentication is unchanged" covers all of this. Developers register their client ID and callback addresses with Login with Amazon in advance, according to the guide, and that arrangement carries on under the new protocol version.
What else is in MCP 2026-07-28
The protocol version Amazon will support is a large revision. Its changelog lists nine major changes, twelve minor ones and four deprecations since the previous revision, 2025-11-25. Amazon's note names the parts that affect how a client talks to its server. It does not address the rest.
Two of these are worth noting for advertising work. The first concerns long jobs. Report generation on the Amazon Ads MCP Server is a multi-step process; the Lite guide says the assistant runs its loop "once to create the report, then again to poll and download the results". Under the new version, if a response stream breaks, clients "MUST re-issue it as a new request with a new request ID", according to the changelog. The second concerns error codes, which were renumbered: UnsupportedProtocolVersion moved from -32004 to -32022, for example. Amazon's note does not say how its server reports a version mismatch.
Thirteen months of the Amazon Ads MCP Server
The December 8 change is the latest in a run of updates. Amazon opened the server as a closed beta on November 13, 2025, with four tool groups: account management, billing, campaign management and reporting. Amazon announced the open beta at the start of February 2026, and its release notes date the open beta entry February 18, 2026. That entry described a "single-shot campaign creation tool" that builds "a complete advertisement - encompassing the campaign, ad group, ad, and targeting - in one call, eliminating what previously required five or more separate operations."
Through all of it the product has stayed in beta. Amazon's documentation still files the server under "MCP Tools (beta)". By contrast, IAB Tech Lab's agent registry listed Amazon Ads MCP in March with a general availability status and the North America endpoint.
