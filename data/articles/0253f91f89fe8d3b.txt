Anthropic's Claude Gets Scheduled Cloud Tasks as Firms Weigh Agent Lock-In
Anthropic's Claude can now be set up to take on recurring work that runs in the cloud while a user's laptop is closed, part of a layered approach the company and outside practitioners are pushing as a way to move customers past one-off chatbot exchanges and into repeatable, auditable workflows.
The framework, outlined in an Anthropic guide and walked through in detail by automation consultant Simon Scrapes, rests on five tiers: the chat prompt itself, shared project context, reusable skills, scheduled autonomous tasks, and finally a user-owned folder of portable files that Scrapes calls an "agentic OS." Each tier is meant to preserve the groundwork laid by the one before it, so that a single well-built brief can be reused rather than rewritten every session.
The most consequential change for enterprise buyers is the fourth tier. Claude app tasks and Claude Code routines now sit together in a scheduled tab, and a task can be triggered by a fixed time, by a GitHub event such as a new pull request or issue, or by an API call. A sales tool, for instance, could fire off a task the moment a lead enters a CRM instead of waiting for a nightly batch. Cloud tasks run by default even when the laptop is shut, and they can use connectors, execute scripts, edit files and work from a selected GitHub repository.
That shift matters because it changes what customers are paying for. A chat subscription sells access; a scheduled task sells labor that happens without anyone present. But it also raises the stakes on governance, since an agent that acts on its own can act wrongly on its own.

Scrapes argues that the older habit of writing short prompts that prescribe each step now works against users, for three reasons: step-by-step instructions confine the model to a single path, omitting the reason behind a task deprives Claude of context it needs when forced to assume something, and Claude 5-generation models tend to overreach unless limits are stated explicitly.
The second tier, Claude Projects, keeps context that is added once available to every chat inside that project. Inputs can include files, task instructions, brand voice, visual identity and live data piped in from connected apps through MCP or APIs; outputs can include drafts, files and live dashboards rendered as artifacts. The distinction between an uploaded file and a connected Google Doc is operationally important: an uploaded CSV is a static copy that will not reflect later edits, while a linked Doc is read fresh each time it is used.
The third tier, skills, separates method from background. Project context describes the business; a skill records how a particular job should or should not be done, and because skills are stored at the account level they can be carried across projects without dragging one client's confidential background into another's work. Anthropic's skill creator includes an eval function that runs the same job with and without a skill against a set of checks, a side-by-side comparison that reveals whether the skill is doing any work at all.
Scrapes recommends building skills from corrections actually made to Claude's output rather than from a blank page, so that the rules are anchored to real failures. Ready-made skills such as Stop Slop already cover broad writing problems like generic opening phrases.
The fifth tier addresses a lock-in problem that the first four create. Under the standard setup, context lives in a Claude project, skills live in a Claude account and scheduled tasks live in the Claude app; switching models would mean rebuilding all of it by hand, and serving multiple clients would mean duplicating everything for each one. The proposed fix is a folder of plain Markdown files that any AI tool can read, pointed at through Claude's code tab. The same files work in Claude Code, Codex and Cursor, so the structure survives a change of interface, model or vendor.
Scrapes is candid that not everyone needs that final layer. A single-business operator with a handful of projects may be perfectly served staying inside Claude, with scheduled tasks handling the recurring work. The question is whether portability is worth the added structure.
Human oversight remains the binding constraint on how far any of this can go. Scrapes said he never delegates anything involving money, complaints or legal matters, or anything published under his name for the first time, and he does not let Claude send most of his emails without approval. Written guardrails reduce risk but do not eliminate it, which argues for manual review of the first several outputs of any new automated task and for starting with work where a mistake is cheap.
The competitive backdrop is intensifying. DeepSeek Harness, an open-source agent framework, has taken a different architectural route by elevating sub-agents from tool plugins to first-class runtime capabilities under what its developers call a Capability Seam design. Providers must declare four boolean capabilities before launch -- structured output, delegation depth limits, tool filtering and independent persona -- and the framework throws an error and refuses to start if a requested capability is not supported, a principle its developers describe as "fail loud, no silent degradation." The harness also ships with Codex and Claude Code providers, letting users dispatch tasks into rival execution engines from a single scheduler.
For Anthropic, the practical risk is not that customers abandon Claude but that they build their workflows in a way that makes leaving cheap. The agentic OS tier, by design, does exactly that. The commercial counterargument is that portability lowers the cost of trying automation in the first place, and that customers who see recurring work completed reliably are more likely to expand usage rather than shop around.
For now the near-term impact lands on operations teams rather than on Anthropic's revenue line. The scheduled tab turns Claude from a tool someone opens into a service that runs on a calendar, and the brief, the project and the skill become the artifacts that determine whether that service is trustworthy.
