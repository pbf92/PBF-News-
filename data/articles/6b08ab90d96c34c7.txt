OUTLET: BigGo Finance

Anthropic's Katelyn Lesse says engineers didn't read 80% of the code behind its Rust rewrite
Anthropic's platform team rewrote the company's entire core API layer from Python to Rust in about five to six months, and the engineers doing the migration barely looked at most of the code. Roughly 80% of the pull requests opened by AI agents were never read line by line, according to Katelyn Lesse, who heads platform engineering at Anthropic, speaking on The Pragmatic Engineer podcast. The other 20%, the load-bearing parts of the system, got deeper attention. The explanation is not carelessness. It is a new model of software engineering in which human effort moves from writing and inspecting code to designing verification that can prove the code works.
That shift matters beyond one company. If the flagship lab behind Claude — the company whose tools are themselves the agents doing the work — has actually operationalized agent-written code at this scale, then the question for every engineering organization is no longer whether agents can write production code, but whether their verification layer is good enough to let them.
Why Rust, and why the compiler became a safety net
The migration was triggered by a CPU crunch, not a language preference. Anthropic's Messages API — the layer every token passes through, powering Claude Code and Claude Desktop for customers — was a Python monolith running in a single Google Cloud region. Request volume spiked hard heading into 2026, with Lesse citing the Super Bowl commercial as one driver, since every app runs through the same API. The team added a second region, then routed traffic between regions (network bandwidth became its own problem), then hunted infrastructure efficiencies. When that ran out, one engineer pushed for something drastic.
Rust over Go, Java, or C++ came down to a clean argument. Anthropic had already started moving new services to Go as it drifted from the monolith, chosen for its midpoint between efficiency and developer experience. Rust was the next step up in efficiency, and the usual objection — that nobody knew Rust and the borrow checker is painful — dissolved because the models could absorb the implementation details. C++ was effectively ruled out on retention grounds: Lesse doubted how many engineers would quit if the order came down.
The deeper point is about verification. In a world of non-deterministic agents, she argues, anything you can make verifiable is where you want to be, and Rust's compile-time checks are exactly that:
"Sure, you have more compile time checks and if you're writing code by hand and going through a really slow iteration loop to get your code to compile, that would be annoying. But in a world where you're not really even paying attention and the model is doing it, the agent is doing it, then that's great because you do have more trust in what you end up with."
She puts the learning split at roughly 75/25: three-quarters of the time the model writes the code and syntax does not matter; the remaining quarter is an engineer's natural curiosity pulling them into the details. She is explicit that she would "be lying" to claim engineers understand every last detail.
Shadow traffic replaced code review as the source of truth
The original plan was to slice off pieces of the system and rewrite them incrementally. A new senior engineer on Lesse's team proposed the opposite — a "great leap" approach. Fork the codebase, rewrite the whole thing in Rust, and put a thin Python front door in front that routes a request through both systems and compares outputs. Drive the divergence rate to near zero, roll out Rust with Python as a fallback for any request that errors, then remove the front door.
The hard constraint was data privacy. Anthropic does not look at customer prompts or completions, so when Python and Rust produced different outputs, the team could not inspect the raw data to debug. Their workaround had two parts: compare everything up to the point where a request descends into inference (where data is inspectable), and on the way out compare token counts. That is a narrow verification surface, and Lesse is candid that it made the work harder.
"The real one big challenge is we don't look at people's problems, we don't look at people's completions. And so if you had a difference, how do you know what about it is different between Python and Rust?"

The migration also had to run alongside continued Python development; at one point a beta went to general availability on the Python side without the Rust team's knowledge, producing a flood of shadow-traffic differences. The fix was linting and static analysis that forced any team shipping a new feature to implement it on both sides — a dual-build period they deliberately kept short.
A Claude classifier now decides whether a human sees your code
Pre-AI, a place like Stripe required human review on essentially every change. Anthropic now runs a Claude-based classifier on every change that decides whether a human needs to look, how many humans, and from which teams — or whether it can merge directly. On mechanical changes, Lesse's example being a mass SDK version bump after a model or API release, the classifier's job is to confirm the change will produce the intended outcome. Riskier changes, or changes in systems where the team is not yet comfortable with zero human attention, get routed to a human.
Lesse frames this as a ratchet: a small number of changes currently merge with no human, and the goal is to push that share up over time. Risky changes still get human eyes.
The pattern extends past merge. Agents fix flaky tests when CI goes red on main, with no human in the loop. A platform acceleration team built QA agents that continuously exercise systems against a human-written specification of intended behavior and open pull requests when something breaks. The pipeline — agents making the change, agents verifying it, agents doing first-pass review, agents deploying, agents monitoring — is what the industry has started calling a "software factory." Lesse confirms the spirit is accurate but says Anthropic does not use the term internally.
On-call is where the human-out-of-the-loop experiment goes furthest
The API on-call rotation is "very load-bearing," and Anthropic has had a Claude shadowing it for many months. The current design is a first gate: a page goes to Claude, which decides noise versus real. Noise gets suppressed, saving humans from being woken for nothing. If real, Claude escalates to a human — and while that human is getting to a laptop, Claude diagnoses the issue, proposes a fix, and sometimes starts acting on it. The human arrives to a recommendation rather than a cold start.
The stated goal is that more and more real issues get handled without waking anyone. Lesse is explicit that they are not there yet; today the system mostly does the triage. This is also where the accountability question gets sharpest, and her answer is organizational rather than technical: the team that owns the system is the team that gets paged, whether the change came from a product manager, an engineer on another team, or an ambient agent with no human involved at all.
Two-pizza teams stayed; the coding interview did not
Team structure is the least-changed thing, Lesse says. Anthropic still runs roughly two-pizza teams of about 5–10 people, because that is still the right number of humans to understand a system, cover on-call, and absorb two people being on vacation. What changed is seniority mix. Where a tech lead used to design and mid-level engineers implement, now anyone on the team is likely doing the design thinking and coordination and orchestrating Claude to build.
Hiring is where the change is most visible. Anthropic has phased out the algorithmic coding interview across all product and platform teams. The reason is signal quality, not ideology: candidates kept crushing every other interview while failing the coding screen, "because they're not writing code by hand all the time anymore." The interview was not deleted outright — it is being replaced by experiments in agent-driven formats: reviewing agent-written code, reviewing an agent-produced system design, or building something with a coding agent. The rest of the loop — technical design, past projects — is unchanged.
Lesse also flags why the old interview persisted at large companies, which is why a clean replacement is hard: leaked questions did not matter much, and interviewers were easy to train to a consistent rubric. The new formats have to hit the same bars on trust, interviewer burden, and bias resistance. That is why several are being tested rather than one swapped in.
Levels and performance reviews survived, with two shifts. The population skews much more senior, so "what does good look like" is less uniform — a problem that used to appear only at staff-and-above now appears broadly. And the old proxy of time spent as a measure of complexity broke: a migration that once took two years now takes five to six months, so the team leans on impact instead — CPU saved, latency improved, incidents avoided — plus qualitative judgment about cross-team coordination. On feedback, Lesse's stated philosophy is that a surprise at review time means the manager failed.
Managed Agents was thrown out and rebuilt because the obvious design failed four ways
Claude Managed Agents is the episode's greenfield case study, and the clearest demonstration of how cheap implementation changes planning. The first design was the obvious one: an API request arrives, spawn a sandbox, boot Claude Code inside it, stream tokens back. It failed on four axes at once.
They shipped early betas of both the Claude Code web experience and the API on the naive design, were unhappy with all four problems, went back to first principles, and rebuilt before going further. Lesse calls it a big decision and does not understate it — but says it was worth it precisely because the rebuild was so much faster than hand-written code would have allowed.
"We found ourselves running on average around a third of the CPU for this system as the original system. And so we threw the whole thing out and we rebuilt it."
The same architecture serves both external API customers and Anthropic's own Claude Code web and mobile experiences, so a session can be fired off in the cloud and picked up later.
Coordination is the job now, and the identity crisis has an answer
Lesse's model of the new engineering job is coordination: getting teams aligned, getting agents aligned, and understanding the mechanics of idea-to-reality well enough to offload the pieces. On the Rust migration, the bulk of engineer time went to cross-team coordination — who is working on what, will this affect you, why is the shadow traffic diverging — not implementation.
"There's still so much work in just like alignment. Like there's the upfront design and getting on the same page that like what are the actual goals and like is the thing that you're going to do solving for those goals?"
She is direct about who struggles: the people having a hard time are those whose identity was "I click-clacked on my keyboard and I wrote code and stuff got done." Her counter is ambition — the point of AI is to get to curing diseases and solving problems long treated as science fiction, and getting there requires engineers to solve security, identity, auth, and infrastructure problems first, because a thousand-agent system without those guardrails produces bad outcomes before good ones. She notes Anthropic's Max plans now include API credits, lowering the barrier for individuals to build persistent agents.
