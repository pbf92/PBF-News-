TITLE: Removing a page from a sitemap won't keep it out of Google Search
OUTLET: PPC Land

Google today moved a set of rules from its oldest Search Central blog posts, written in 2005 in the first months of its sitemap program, into the official sitemaps documentation. The changelog entry names two of them: a sitemap index file cannot point to another sitemap index file, and an HTML sitemap page is not something Google will accept as a submitted sitemap. The same update added a line to the sitemaps overview page that matters to anyone trying to pull a page out of Google's results: leaving a web address out of a sitemap does not stop Google from crawling or indexing it.
In Short
Google copied advice that still holds from its 2005 blog posts into its official sitemap help pages today, including that an index file cannot list other index files and that an HTML sitemap page cannot be submitted to Google as a sitemap. This affects publishers, online shops and anyone running a large website, because sitemaps are how many of them tell Google which pages exist. The overview page now also says that taking a page out of a sitemap does not keep it out of Google; a noindex instruction on the page does that. One of the 2005 posts said the opposite on index files, so the old blog post and the current rules disagree.
What Google changed
A sitemap is a file that lists the addresses of a website's pages, so search engines can find them without following every link. Large sites split that list across many files and tie them together with a sitemap index file, which is a list of sitemap files rather than a list of pages.
The change appears on Google Search Central's "Latest documentation updates" page under November 27, 2026, with the heading "Ported still-relevant guidance from 2005 blog posts." According to Google, the entry reads:
"What: Ported information that's still relevant today from our oldest blog posts (from 2005!) to our sitemaps documentation, such as that nested sitemap index files aren't supported and HTML sitemaps can't be submitted in Search Console."
"Why: To preserve still-accurate guidance from early Search Central blog posts in our documentation."
The wording "such as" matters. The two examples are not the full list, and the changelog does not name the posts that were used. To find what else moved, PPC Land compared the three sitemap pages that now carry a "Last updated 2026-11-27 UTC" footer with their previous English versions.
The Italian, Spanish and Japanese versions of the sitemap index page were last updated on February 20, 2026, and none of them contains the nesting sentence. Translations of Google's documentation often trail the English pages.
The nesting rule and the 2005 post that allowed it
The most consequential line sits on the sitemap index page. According to Google's documentation, an index file can only list individual sitemaps; an index file that points to another index file is not supported. The rest of that page is unchanged: the sitemaps an index lists must be hosted on the same site as the index and sit in the same directory or lower in the site's folder structure, an index file may contain up to 50,000 entries, and a site can submit up to 500 index files in its Search Console account.
Those limits leave little practical need for nesting. Five hundred index files, each listing 50,000 sitemaps of 50,000 URLs, add up to 1.25 trillion URLs per site through Search Console alone (PPC Land calculation from Google's published limits). Microsoft put its own ceiling at 2.5 billion URLs through a single Bing index file when it stressed the role of sitemaps in AI-powered search in July 2025.
What makes the line notable is its history. On August 18, 2005, Vanessa Fox published a post titled "Using Sitemap Index Files" on Google's Inside Google Sitemaps blog, the predecessor of today's Search Central blog. Under a heading about creating an index of index files, the post told webmasters that this was possible, and that an index file, like a sitemap, could be no larger than 10MB. The guidance Google now calls still relevant is the reverse of what that post said.
The changelog does not explain the gap. Google may have drawn on a later 2005 post that is not part of this comparison, or it may have recorded the rule as it has applied for years. Support was gone by November 2020, when Google's John Mueller replied on Twitter that nested index files were not supported, according to Search Engine Roundtable, which reported the exchange on December 1, 2020. More recently, on Google's Search Off the Record podcast on October 1, 2026, Mueller said sitemaps can only be nested once and that a site can submit as many index files as it wants, remarks PPC Land covered when it reported that Google may skip sitemaps on sites it deems low quality. The documentation is more specific on both points: one layer of index files, and up to 500 index files per site in Search Console, with no stated cap on sitemap lines in robots.txt, the plain text file that tells crawlers which parts of a site they may fetch. Until today, the nesting rule was not written down there.
Google has not said what happens to a nested index file that a site has already submitted. The documentation states only that the structure is not supported.
HTML sitemaps: a page for people, not a file for Google
An HTML sitemap is an ordinary web page with links to a site's main sections, often linked from the footer. The XML sitemap that Google reads is a separate file in a set format. The two share a name and little else.
Google's position here has not moved since 2005. On September 26, 2005, a post titled "How is a Google Sitemap different from an HTML sitemap?" said Google encouraged HTML sitemaps for users but that they could not be submitted to the Google Sitemaps program. For site owners unable to produce a file in the sitemap format, that post pointed to a plain text file listing URLs as the alternative. The text format remains in the documentation today, alongside XML and feed formats.
The updated "Build and submit a sitemap" page now says the same thing in current terms: an HTML sitemap can help visitors and search engines move around a site, but it is not a format Search Console accepts. Mueller has described HTML sitemaps in similar terms on Google's podcast. In July, while explaining why Google dropped a 2007 rule requiring blocked internal search pages, he listed an HTML sitemap as one optional part of a well-structured site, next to a sitemap file. In October he said HTML sitemaps do not replace the XML file.
Removing a URL from a sitemap does not remove it from Google
The overview page is the most widely read of the three, and its new sentences address a common misunderstanding. According to Google's "Learn about sitemaps" page:
"A sitemap helps search engines discover URLs on your site, but it doesn't guarantee that all the items in your sitemap will be crawled and indexed. However, in most cases, your site will benefit from having a sitemap. Also, omitting or removing a URL from your sitemap doesn't prevent Google from crawling or indexing it if Google discovers the URL through links from other web pages. To keep a page out of Google Search, block indexing with noindex."
In plain terms, a sitemap is an invitation, not a gate. Google finds pages through links as well as through sitemaps, so a page that other sites link to can stay in search results long after a publisher drops it from the sitemap. The noindex instruction, a tag in the page or a header sent by the server, is what tells Google not to show the page.
The same logic runs through earlier PPC Land coverage. In 2024 Mueller explained that Google may index pages it has been told not to crawl, because a crawler that is blocked from fetching a page never sees its noindex tag and can still index the address from links. In October 2026, Google's spam prevention guide went further and told platforms to noindex link-shared pages by default, or block them from crawling. The overview page now gives the same instruction for sitemaps.
None of this was in the earliest guidance. On August 26, 2005, a post titled "What URLs should a Sitemap include?" urged webmasters to list everything, including content, images and media, and reminded them that Google respected robots.txt rules for any URL in a sitemap. It did not discuss what happens when a URL is left out.
Compression and the 50MB ceiling
The gzip sentence also has roots in the first year of the program. A post from August 25, 2005, titled "What's in a name?", said a sitemap could have any name except robots.txt, recommended an .xml extension for XML sitemaps and .xml.gz for files compressed with gzip, and gave sitemap.xml.gz as the default name. The new line in the documentation uses the same example.
The size limit has changed more. In 2005 a single sitemap could be no larger than 10MB uncompressed. In November 2016 Google and Bing raised that to 50MB, according to Bing's webmaster blog, a fivefold increase (PPC Land calculation). Today's documentation adds that the 50MB ceiling applies to the uncompressed file. A sitemap that compresses to 12MB but expands to 60MB is still over the limit.
The size sentence changed as well: the limit used to be stated for all formats and is now stated for all supported formats. The edit fits the new HTML paragraph: Google is drawing a line between the formats it reads as sitemaps and pages that merely resemble them.
How the documentation describes building and submitting a sitemap
Read together, the three updated pages describe the process in six steps. This is a record of what the documentation says, as of November 27, 2026.
- Deciding whether a sitemap is needed. Googlebot, Google's main crawler, finds pages by following links from pages it has already crawled, so a sitemap mainly helps where links are thin. According to the overview page, a site "might need a sitemap" if it is large, if it is new with few external links, or if it has "a lot of rich media content (video, images) or is shown in Google News." Large sites matter because, in Google's words, "it's more likely Googlebot might not discover some of your new pages." The page defines a small site as "about 500 pages or fewer," counting "only pages that you think need to be in search results." It adds that content management systems "such as WordPress, Wix, or Blogger" have likely made a sitemap available already.
- Choosing a supported format. The build page lists three: XML, RSS, mRSS and Atom 1.0 feeds, and plain text files that list only URLs. Files must be UTF-8 encoded. An HTML sitemap page is not one of the supported formats.
- Staying within the size limits. Each sitemap is limited to 50MB uncompressed or 50,000 URLs. Files can be compressed with gzip; the limit still applies to the uncompressed size. Larger sites split their URLs across several sitemaps.
- Grouping sitemaps with an index file. An index file lists individual sitemaps only, never other index files. The listed sitemaps must be on the same site, in the same directory as the index or below it. An index can hold up to 50,000 entries.
- Submitting. Sitemaps can be submitted through the Sitemaps report in Search Console, through the Search Console API, or by adding a "Sitemap:" line to the site's robots.txt file. Search Console accepts up to 500 index files per site. The documentation describes submission as only a hint that does not guarantee Google will download the file or crawl the URLs in it. Google says it ignores the priority and changefreq fields and uses lastmod only when the dates are consistently and verifiably accurate.
- Keeping pages out. Leaving a URL out of the sitemap is not enough to keep it out of Google Search. The overview page says to "block indexing with noindex."
