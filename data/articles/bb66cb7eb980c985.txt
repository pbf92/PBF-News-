TITLE: Cisco and OpenAI dispatch AI agents to shield vulnerable systems before permanent patches arrive
OUTLET: InfoWorld

Autonomous AI agents are rapidly and dramatically transforming the cybersecurity landscape for both defenders and adversaries.
In hopes of giving security teams a head start and pitting machine against machine, Cisco and OpenAI have released a new open source project, dubbed Shirudo (Japanese for “shield”). The Shirudo platform launches small, temporary mitigations to help protect systems until patches can be deployed. AI agents can replace flawed code with fixed code, which human teams can test and approve (or not), then deploy, setting boundaries and holding onto the keys, with no need for a hard reset.
The project has already been proven to block a Java4Shell exploit attempt against the search and analytics platform Elasticsearch, while the site continued to run as usual.
Need to buy time
“For years, we’ve treated security like a coat of paint,” Cisco president and CPO Jeetu Patel wrote in a blog post. “You first build infrastructure, then wrap security around it.”
But, he asserted, this approach is “fundamentally mismatched” to AI. Security should live inside the infrastructure itself. “If protection sits outside the system, it’s always a step behind,” he said.
He noted that AI agents are getting better at discovering security vulnerabilities; for instance, startup Calif used AI to help discover the PHP2Shell flaw and a major Java bug.
Dovetailing with this, the agents themselves are both a risk vector and an adversarial actor. Attackers are using swarms of them to exploit discovered flaws; with both PHP2Shell and Java4shell, campaigns were underway “within a day of disclosure, if not before,” he pointed out. Flaws unfold over minutes and hours, as opposed to the days and weeks of the past, but permanent fixes take time to build, test, and roll out.
“We need ways to shield systems and buy our teams time to get patches in place,” Patel said.
Making the infrastructure secure from the start
Shirudo combines Cisco’s infrastructure with OpenAI’s frontier models and AI research. It is built on extended Berkeley Packet Filter (eBPF), which supports the running of small, sandboxed programs inside a Linux kernel without changing source code or loading additional modules.
“This makes it possible to observe suspicious activity and apply targeted security protections to running systems,” OpenAI explained in its blog post announcing the project.
Speaking in their own language, guardian agents investigate and detect flaws and build shields, then test whether they stop the attack, all without disrupting the targeted service. The shields are cryptographically signed and only loaded when verified and deemed safe. Linux’s eBPF verifier checks eBPF programs against safety rules, and kernel security controls restrict unauthorized changes.
Shirudo also uses a Trusted Platform Module (TPM) to support a verifiable record of protections being added or removed.
All this takes place even if attackers have already gained access to a system.
Further, self-defending agents can monitor for false positives, performance, and overall system health, and incorporate red-team findings and other feedback as well as signals for continuous improvement. Evidence backing every control travels across the system.
The idea, according to Cisco and OpenAI, is to make the infrastructure itself secure by default. “We want to strengthen the operating system foundations needed to deploy these protections at scale, including hardening the kernel and core services, limiting workload permissions, and making updates and recovery safer,” OpenAI wrote in its post.
Shirudo in the wild
Shirudo has its roots in Tetragon, an eBPF-based security platform developed and open-sourced by Isovalent, which was acquired by Cisco in 2024. It is already incorporated into Cisco’s Live Protect capability.
But Tetragon has been rewritten for the agentic era; its previous iteration pointed AI to human-oriented consoles, configuration files, and policy languages. In that workflow, the agent thought in machine code, which was then decoded for humans and processed, then translated back again into machine code. With Shirudo, agents interact in their natural language, which is code.
“Agents are different,” Isovalent co-founder Thomas Graf and its chief open source officer Liz Rice noted in a blog post: They are very good at generating code, can absorb huge amounts of context quickly, and “[don’t] mind reverse engineering several million lines of assembly code.”
In one controlled testing environment, researchers fed information about the Java4Shell vulnerability into Shirudo, which automatically created a shield against exploitation, generating a mitigation in Java bytecode which was injected into any Java app and added validation on the base64 input to guard against exploit attempts by threat actors.
Graf and Rice explained that agent loops can either be tasked to actively search for new vulnerabilities on their own, or work off external sources like newly-available security disclosures. Agents can generate mitigation code, reproduce and validate exploits, and determine the most effective patching measures. This step is repeated until the agent identifies a successful path. The shield is then signed and securely rolled out to vulnerable nodes; it retires when a patch is installed.
“This step is continuously monitored and repeated to achieve the highest possible security score while closely monitoring the health of applications,” Graf and Rice explained. It can be designed to be “more or less autonomous.”
Once mitigation shields are deployed, the system employs a “hit” count of active exploitation attempts, so that exploits can be investigated on demand.
Ultimately, the Shirudo project is only the beginning, Graf and Rice noted, but it already shows “true potential” and the hope is it will continue to evolve in the open source ecosystem. “We believe that building secure infrastructure for the AI era is an industry-scale problem,” they said.
