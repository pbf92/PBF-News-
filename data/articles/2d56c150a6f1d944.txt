LinkedIn Builds View-Agnostic Analytics for Virtual Nodes
The system uses a shared MeasurableNode contract so UIKit views and virtual UI elements can be tracked in the same analytics framework.
Updated on Nov. 23, 2026 in Software
LinkedIn engineers have built an analytics system that no longer requires every measurable element to be a UIView. Instead, both UIViews and virtual nodes participate through a shared MeasurableNode contract exposing identity, geometry, hierarchy, and lifecycle.
Why it matters
Modern UI architectures flatten layouts and use custom rendering, so many elements never materialize as UIViews, which can cause traditional analytics to miss impressions, lose context, miscalculate visibility, and misattribute user actions. The approach offers a way for app developers working with UIKit to keep analytics accurate as interfaces become more virtualized.
The contract exposes four properties (identity, geometry, hierarchy and lifecycle) that let virtual nodes participate alongside UIViews. UIKit automatically sends lifecycle notifications to UIViews, but virtual nodes are not directly recognized as gesture-recognizer targets.
The players
LinkedIn is a professional networking platform owned by Microsoft whose engineering teams publish technical write-ups on their mobile infrastructure.
The details
Developers faced three main challenges: embedded UIView assumptions in existing code, balancing short-term compatibility with long-term correctness, and enforcing attach and detach discipline at the framework level. The rendering framework traverses the hybrid UIKit and virtual-node hierarchy to attribute user actions to the correct logical node, while attach and detach methods notify the analytics system when nodes appear, change frame, or leave.
The Tech Race
The change extends UIKit's long-standing UIView-centric model, which Apple's framework has relied on since the iOS SDK's early releases, to accommodate the flattened, custom-rendered interfaces that modern apps increasingly use. It positions mobile analytics tooling to keep pace as developers move away from one-view-per-element layouts.
App users benefit when analytics correctly record what they actually see and tap, which can shape which features and content they encounter next. Developers building mobile apps gain a framework-level pattern for keeping measurement accurate as interfaces grow more virtualized.
The takeaway
Analytics that work across both UIKit views and virtual nodes depend on a shared contract rather than on every element being a view. Teams building flattened, custom-rendered interfaces should plan for lifecycle and hierarchy tracking from the start.
